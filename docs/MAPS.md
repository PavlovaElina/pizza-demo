# Яндекс Карты и адреса

## Настройка

1. Получите ключи JavaScript API, HTTP Геокодера и Геосаджеста в кабинете разработчика Яндекса. Проверьте условия использования и квоты своего аккаунта.
2. Скопируйте .env.example в .env.local в корне проекта.
3. Заполните переменные:

```dotenv
YANDEX_MAPS_API_KEY=browser_map_key
YANDEX_GEOCODER_API_KEY=server_geocoder_key
YANDEX_SUGGEST_API_KEY=server_suggest_key
```

.env.local исключён из Git. Серверные ключи нельзя помещать в переменные с префиксом VITE_ или frontend-код. Браузерный ключ намеренно доступен клиенту; ограничьте его разрешёнными доменами, включая localhost для разработки и домен размещённого демо.

При IP-ограничениях серверных ключей нужен внешний IP сервера. После изменения ключей перезапустите Node.js. Изменения ограничений в кабинете могут применяться с задержкой.

## Контракт API

| Метод | Путь                  | Данные                                      |
| ----- | --------------------- | ------------------------------------------- |
| GET   | /api/location/config  | Публичный ключ карты и доступность сервисов |
| POST  | /api/location/geocode | query, cityId                               |
| POST  | /api/location/reverse | lat, lng                                    |
| POST  | /api/location/suggest | query, cityId                               |

Сервер обращается только к фиксированным HTTPS endpoint Яндекса. Ответы нормализуются, серверные ключи и полные ответы провайдера клиенту не возвращаются. Размер тела запроса ограничен 8192 байтами; upstream-запросы имеют таймаут.

Для трёх POST-методов действует общий бюджет 60 запросов за 60 секунд на один процесс сервера. При превышении возвращаются HTTP 429 и Retry-After в секундах. Лимит общий для всех посетителей и сбрасывается при перезапуске; это защита небольшой демонстрации, не распределённая система ограничения трафика. Некорректные запросы тоже расходуют бюджет; при отсутствии нужного ключа возвращается 503.

## Поведение интерфейса

Геолокация запрашивается только по кнопке. Предполагаемый город применяется после подтверждения; ранее выбранный город автоматически не меняется. Точные координаты пользователя не сохраняются в browser storage.

Подсказки запрашиваются после паузы 400 мс для ввода от трёх символов. Доступны мышь, стрелки, Enter и Escape. Выбор подсказки запускает геокодирование. Клик по карте и перенос метки определяют адрес; ручной поиск ставит метку.

Координаты SDK имеют порядок [долгота, широта], состояние приложения — {lat, lng}. Новый запрос имеет приоритет; устаревший ответ не перезаписывает выбор. Ручная правка снимает привязку к прежней точке. Ошибка сервиса не стирает введённый адрес.

Геокодированный адрес проверяется на соответствие городу. Без сервиса ручной адрес связан с выбранным пользователем городом, но фактическое положение дома не подтверждается. Филиалы вымышленные; проверка реальной зоны доставки отсутствует.

## Проверка интеграции

Автотесты используют подмену SDK и ответов адресного API. После настройки собственных ключей отдельно проверьте настоящую карту, адресные подсказки, точку → адрес, адрес → точку, перенос метки и отказ геолокации. Обозначения и ссылки Яндекса должны оставаться видимыми.

Без ключей и при недоступности сервисов сохраняется ручной ввод. Для размещения нужен Node.js и HTTPS: [инструкция](HOSTING.md).

Официальная документация: [JavaScript API](https://yandex.ru/maps-api/docs/js-api/quickstart.html), [HTTP Геокодер](https://yandex.ru/maps-api/docs/geocoder-api/quickstart.html), [Геосаджест](https://yandex.ru/maps-api/docs/suggest-api/index.html).
