# Доступ к сайту с других устройств

## Быстрый запуск на macOS

В Finder откройте папку проекта, затем scripts и дважды нажмите serve.command. Он собирает сайт и запускает сервер на http://localhost:3003. Оставьте окно Terminal открытым. Этот порт отличается от API режима разработки, поэтому они могут работать одновременно.

Если двойной клик недоступен, откройте Terminal, введите zsh и пробел, перетащите файл serve.command в окно и нажмите Enter.

При установленном cloudflared откройте второе окно Terminal и выполните:

```sh
cloudflared tunnel --url http://localhost:3003
```

Скопируйте напечатанную HTTPS-ссылку, разрешите её домен для JS-ключа Яндекса и проверьте сайт с телефона через мобильный интернет. Это ссылка для посетителей; localhost на их устройствах указывает на их собственное устройство.

Не закрывайте оба окна и крышку Mac во время показа. Чтобы остановить показ, нажмите Ctrl+C сначала в окне туннеля, затем в окне сервера. Следующий запуск туннеля создаст новую ссылку.

## Локальный сервер

Требуется Node.js 24+. Выполняйте команды из корня проекта:

```sh
npm ci
cp .env.example .env.local
```

Копирование .env.example нужно только при первой настройке: не перезаписывайте заполненный .env.local. Укажите ключи по MAPS.md, затем:

```sh
npm run build
npm start
```

Node.js выдаёт только dist/ и адресный API на http://localhost:3001. Корень проекта и .env.local не раздаются. После изменения frontend нужна новая сборка; после изменения сервера или ключей — перезапуск процесса. Остановка — Ctrl+C.

На macOS, чтобы не допускать автоматического сна во время демонстрации:

```sh
caffeinate -i npm start
```

Держите Mac включённым, с открытой крышкой и подключением к интернету.

## Временная HTTPS-ссылка

Установите cloudflared по [официальной инструкции](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/). При работающем сервере откройте второй Terminal:

```sh
cloudflared tunnel --url http://localhost:3001
```

Команда напечатает временную HTTPS-ссылку trycloudflare.com. Её можно открыть на телефоне или другом компьютере, включая устройства вне домашней сети. Любой человек со ссылкой сможет открыть демо. Публичный доступ прекращается при остановке туннеля.

Quick Tunnel не требует аккаунта или домена, но адрес меняется при новом запуске и доступность не гарантируется. Разрешите фактический домен ссылки в ограничениях браузерного ключа Яндекса. После изменения ограничений отдельно проверьте карту и оформление на новом адресе. Для регулярных демонстраций удобнее постоянный домен и настроенный постоянный туннель или Node.js-хостинг.

Обычный HTTP-адрес домашней сети не обеспечивает secure context для Service Worker и геолокации. Этот проект использует Service Worker для демонстрационного API, поэтому HTTPS нужен для полного сценария на удалённом устройстве.

## Ограничения

Сервер по умолчанию слушает только loopback; туннель соединяется с ним локально. Vite dev-сервер публиковать не требуется. Общий лимит адресного API — 60 запросов в минуту на процесс; он не заменяет квоты провайдера и инфраструктурную защиту.

GitHub хранит код. GitHub Pages не запускает этот Node.js-сервис; одного размещения dist/ для адресных сервисов недостаточно. Контакты, филиалы, заказы и оплата остаются демонстрационными.

Источники: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), [secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts).
